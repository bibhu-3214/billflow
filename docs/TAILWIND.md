# Tailwind development

The web frontend uses Tailwind CSS 4.3.3 and `@tailwindcss/vite` 4.3.3. Material UI, its icon library, JSS theme and SweetAlert styles have been removed. React remains at version 17. React Native retains its platform-native styling.

- `vite.config.mjs` registers Tailwind before the React plugin. The connected development proxy preserves the browser host so local sign-in passes same-origin CSRF checks on both `localhost` and `127.0.0.1`. No PostCSS or JavaScript Tailwind configuration file is needed.
- `src/styles.css` imports Tailwind and defines CSS-first theme tokens, base styles, reduced-motion behavior and quotation-print rules through Tailwind utilities and `@apply`. Custom animations are registered in `@theme static` with CSS keyframes, following [Tailwind’s theme configuration](https://tailwindcss.com/docs/theme#defining-animation-keyframes). Print page size/margins remain `@page` metadata.
- `src/styles/recipes.ts` contains literal Tailwind class lists for shared layouts and semantic component hooks. Those hooks remain available to browser tests; their styling is generated from Tailwind utilities.
- `src/styles/ui.ts` expands recipe names and uses `tailwind-merge` for utility conflict resolution. Use `ui('surface-card', 'p-6', condition && 'border-primary')` for shared recipes; use literal utilities for simple elements.
- `src/components/ui/primitives.tsx` provides typed buttons, fields, switches, tables and pagination. SelectControl and DateControl style dropdowns and date entry with Tailwind; unstyled Radix primitives provide menu/popover keyboard and focus behavior, while the lazy-loaded DayPicker calendar receives only Tailwind class names. Dialog focus/dismissal behavior comes from Radix; notifications use the same Tailwind dialog host. Icons come from Lucide. `Disclosure.tsx` provides the shared Tailwind summary, visible keyboard focus, native Enter/Space behavior and a chevron that rotates only for its own open disclosure. All ten disclosure controls use it.

Use complete class strings so Tailwind can find them at build time. Do not assemble utilities such as `h-${value}`. Runtime chart measurements and tooltip coordinates use inline values/custom properties; their appearance stays in utilities. Finite layouts and animation delays use literal utility lists.

The `dark:` variant follows `data-theme="dark"` on the document root. `AppearanceProvider` retains the existing system preference, browser preference and cross-tab behavior. Use theme tokens (`bg-field`, `bg-surface`, `text-ink`, `border-line`) for new controls. Financial previews and print pages retain an ink-on-white document palette.

Keep labels associated with controls, helper/error text linked by `aria-describedby`, button names meaningful, and focus styles visible. Visible dropdowns use headless select triggers and portaled Tailwind option panels with keyboard navigation. Hidden native selects preserve actual form values and validation events; date fields validate local YYYY-MM-DD dates without UTC conversion. File input buttons and inline validation messages also use shared Tailwind utilities. The operating-system file chooser and print dialog remain system UI. No component-library stylesheet is imported. Pass dismissal requests through the editor's dirty/busy guard.

Run `yarn check`, `yarn test --runInBand`, `yarn test:tooling`, `yarn build` and `yarn build:connected`. With the disposable acceptance API running, `yarn test:browser` covers connected financial workflows, responsive layouts, dark-mode persistence, dialog keyboard behavior and quotation printing. See [validation setup](VALIDATION.md). Review desktop, tablet and phone screenshots after shared utility changes.

Authenticated pages use a shared desktop sidebar/mobile navigation rail. New overview components use semantic theme tokens directly rather than adding overrides to the migrated legacy recipes. Chart heights remain data-driven CSS properties; all finite layouts use literal utilities. Route pages load lazily, and the page error boundary preserves navigation after a failed chunk.

Runtime chart sizes and tooltip coordinates, Radix positioning/scrollbar mechanics, jsPDF export settings and operating-system dialogs are rendering requirements rather than replaceable static component skins. Do not hide or approximate financial values to eliminate a runtime style. The separate React Native client uses its own style system; a NativeWind migration is a separate platform change.
